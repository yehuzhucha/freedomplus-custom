# 抖音模块适配经验教训（2026-10 汇总）

> 来自抖音 36.8.0 定制：长按菜单、双击不点赞、视频信息、无水印下载、续火花五条链路。
> 踩过的坑都在这，下次换版本照着做能少走很多弯路。

## 一、逆向定位：先找类，再找方法，最后看签名

```bash
# 1. 类在哪个 dex（快，不反汇编）
for f in alldex/classes*.dex; do
  dexdump "$f" 2>/dev/null | grep -q "Class descriptor.*你要的类名" && echo "$f"
done

# 2. 方法签名（关键：参数类型 + 返回类型）
dexdump -d classesXX.dex | awk '/Class descriptor.*目标类/{f=1} f{print} f&&/source_file_idx/{exit}' | grep -E "name|type"
```

**教训：不看返回类型就 hook，一定白干。**

- `onLongPressIntercept(float,float)` 返回 **boolean** → `setResultVoid()` 等于「没拦截」，必须 `setResult(true)`
- 同名方法可能有多份（不同参数），按 `parameterCount` + 类型过滤

## 二、混淆名不可靠，运行时扫字段更稳

长按菜单那次，抖音把弹窗回调放在 `FeedLongPressLayoutPresenter` 的**第二个** `(float,float)->void` 回调里，
第一个回调只管广告拦截。fplus 一直挂错。

**正确做法**：运行时遍历 `LongPressLayout` 的所有字段，凡是 `(float,float)->void` 类型的对象就 hook，
不管它叫什么名、放在哪个字段。换版本也不会失效。

## 三、发送类功能：回调 > 轮询

续火花最初用 `getMsgStatus()` 轮询，两个问题：

1. **这个调用本身会卡死**（3 分钟不返回）
2. 轮询拿不到真实结果，于是「提交成功」被当成「送达成功」

**正确做法**：用 SDK 的 `IRequestListener` 回调（`onSuccess` / `onFailure`），配 15 秒超时。

## 四、工具类入口会随版本搬家

| 版本 | 取 `IMessageUtils` 的入口 |
|---|---|
| 抖音 30.x ~ 某版本 | `MultiInstanceHelperKt` 上的静态方法 |
| **抖音 36.8.0** | **`X.12pl.LIZ()`** |

照抄开源项目（SparkFlame / doumcp）在 36.8.0 上直接失效，报「取不到 IMessageUtils」。

**教训：开源项目给的是思路，不是常量。换版本必须重新反查 dex。**

```bash
# 找谁返回某个类
dexdump -d classes35.dex | grep -A1 "invoke-static.*你要的类"
```

## 五、消息构造别手写 JSON

```java
// ❌ 手写：{"text":"...","type":700}
// ✅ 用宿主自己的模型：
TextContent content = new TextContent();
content.setText(text);
String json = GsonUtil.INSTANCE.toJson(content);
// 产物：{"type":0,"instruction_type":0,"item_type_local":-1,"text":"..."}
```

手写的 JSON 抖音能收，但字段不全，容易出现「提交了但发不出去」。

## 六、日志必须上报服务器

只写本地 `/sdcard/...` 的日志，用户不发给你就等于没有。
**每个关键节点都 POST 到服务器**（`stage` + `detail`），排查时不用来回要文件。

这次续火花最后靠 `diag` 上报才定位到「取不到 IMessageUtils」——本地日志用户嫌麻烦不发。

## 七、长任务会被系统杀

续火花 10 个好友要跑几分钟，抖音在后台容易被 Android 回收，
日志里表现为「跑到第 6 个就没了」，之后每次启动都显示「今天已跑过」。

**对策**：发送期间保持前台；把单轮时长压短（间隔 10~20 秒，10 个人 3 分钟）。

## 八、状态文件不能写 /sdcard

Android 13+ 抖音没有 `MANAGE_EXTERNAL_STORAGE`，`/sdcard/Download` 写入直接 `EACCES`。
**必须用 `getExternalFilesDir()`**，否则「今日已发」记录丢失，重开就重复发。

## 九、免 root 框架：LSPatch vs NPatch

```
LSPatch   只认老 API（assets/xposed_init）
NPatch    支持新 libxposed（META-INF/xposed/）
```

用 Modern API 102 写的模块（如静盒 QuietBox）**只能 NPatch 内嵌**。

NPatch 签名绕过等级：

```
-l 0 无 / 1 基础 / 2 高 / 3 极端 / 4 Seccomp / 5 Stealth（5 必须 --manager，不能内嵌）
```

自定义 keystore **只认 BKS**（JKS 报 `Wrong version of key store`）。

## 十、构建与发布流程

```
改代码 → git push → GitHub Actions 编译 → 下载 artifact
      → LSPatch 内嵌到基础包（-l 2 --version-code 900500）
      → 放到 /var/www/dl/ → 给用户链接
```

**versionCode 固定 900500 + 同一个签名** ⇒ 任何版本都能覆盖安装，用户不用卸载。

## 十一、排查方法论

1. **先隔离变量**：无模块包 / 有模块包，官方原版 / 补丁版
2. **先证明服务端**：日志、回调、返回码，再怀疑网络和设备
3. **一次抓全**：诊断版把所有候选路径的结果都上报，别一版试一个
4. **别信「日志全绿」**：成功判定必须来自宿主的明确回调，不是「没抛异常」
