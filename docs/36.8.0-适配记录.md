# 抖音 36.8.0 适配全过程（2026-10-29）

记录一次完整的「把 Freedom+ 内置模块从官方支持的 30.9.0/40.6.0 移植到 36.8.0」的实测过程。
包括每一版的改动、现象、根因和最终结论，方便以后换版本时复用方法论。

环境：抖音 36.8.0（vc 360801，versionName 伪装 90.5.0 / vc 900500），
LSPatch 本地模式（`-l 2`）内置模块，覆盖安装。

---

## 0. 起点

Freedom+ 官方支持版本：`28.0.0~30.3.0`、`40.6.0`。**36.8.0 不在列表内**，
DexKit 的类定位大面积失配，表现为四个功能全废：

```
① 视频信息   查不出（aweme 为 null）
② 无水印下载 拿不到播放地址
③ 双击视频   打开评论的同时也点赞了
④ 长按视频   模块菜单 + 抖音原生菜单 双弹
```

## 1. 关键工具链

```bash
# 反编译（1 核 2G 时跑不动，扩到 4 核 24G 才稳）
jadx -j 4 -Xmx12g -d out --no-res --no-imports classesXX.dex

# 定位某个类在哪个 dex（比全量反编译快得多，7 秒/dex）
dexdump classes17.dex | awk '/Class descriptor/{c=$0} /目标类名;/{print c}'

# 打包（LSPatch 本地模式，内置模块）
java -jar lspatch.jar -m module.apk -l 2 --version-code 900500 -o out/ base.apk
```

**踩过的坑**：后台任务的 systemd scope 默认 `MemoryMax=4G`，给 jadx 设 14G 堆也会被
cgroup OOM 杀掉（`Memory cgroup out of memory: Killed process (java) anon-rss:4029292kB`）。
要用 `systemd-run --user --scope -p MemoryMax=18G` 单独开 scope。

## 3. 四个根因（最有价值的部分）

### 3.1 长按：hook 在了错误的位置

反编译 `FeedLongPressLayoutPresenter` 的构造函数：

```java
this.q = new OnLongPressInterceptListener() {          // ← 原模块只挂了这一个
    public boolean onLongPressIntercept(float f, float f2) {
        ... // 只返回"要不要拦截广告/付费视频"，不弹窗
        return false;
    }
};
this.s = new X.0Vjd() {                                // ← 面板其实从这里弹
    public void LIZ(float f, float f2) {
        X.13vb panel = new X.13vb(context, fragment, ...);
        X.13va.LIZ(panel);                             // 真正的弹窗
    }
};
```

**fplus 一直在挂错的回调。** 它在 40.6.0 上能用，是因为那个版本弹窗逻辑恰好在 `q` 里面。

另外 `onLongPressIntercept` 返回 **boolean**，原来调 `setResultVoid()` 等于告诉抖音
"我没拦截"，所以原生面板照常弹。

**解法**：运行时扫 `LongPressLayout` 的字段，凡是带 `(float,float)->void` 方法的对象全挂上，
`setResultVoid()` 吃掉。不依赖任何混淆类名。

### 3.2 双击点赞：hook 在抽象基类上

```java
handleDoubleClick(MotionEvent)
  → handleDoubleClickInner()
    → handleBigDiggViewClick(MotionEvent, IFeedViewHolder, Aweme)   // 点赞在这
```

`BaseListFragmentPanel` 是 **abstract**，真实实例是子类。如果子类重写了
`handleDoubleClick`，挂基类的 hook 不会触发。

**解法**：直接挂 `handleBigDiggViewClick`——子类不重写它，挂基类即可覆盖所有实例。

### 3.3 视频信息：`aweme` 拿不到 + 第三方接口已死

- `aweme` 原本从长按回调对象的字段取，而那个回调从来没触发过 → 一直是 null。
  改为 hook `FeedLongPressLayoutPresenter.onBindSafe`（每次绑定新视频都会调用）抓取，
  静态共享 + 视图层级兜底。
- `api.ip33.com` **DNS 都解析不出来了**（`getent hosts` 无结果，curl 返回 000），
  属地查询必然返回空串。改为自建中转：`https://<自建域名>/area/?code=<city>`。

### 3.4 续火花：会话查询在 36.8.0 上会挂

```java
// 旧逻辑（36.8.0 失效）
center.getConversationListModel()      // 返回 null，有时直接不返回
waitConversation(client, center, cid, 180);   // 等满 180 秒 → 抛"会话未出现在本地模型"
```

`SendMsgHandler` 第一步就是按会话ID查本地会话模型，查不到必然失败。

**解法**：不查了，直接用会话ID字符串设置（30.9.0 时代的老做法）：

```java
builder.conversationId("0:1:111188513589:1508947254054596")
```

36.8.0 上命中的方法就是 `conversationId(String)`，改完 10 个好友全部送达。

## 4. 两个隐蔽的环境坑

### 4.1 Android 13+ 写不了 `/sdcard/Download`

抖音只声明了 `WRITE_EXTERNAL_STORAGE`，**没有 `MANAGE_EXTERNAL_STORAGE`**，
而 Android 13 起前者完全失效。

后果：
- `spark.log` 停在很久以前 → 看起来像"模块没跑"
- `spark-sent.json`（已发记录）写不进去 → **每次重开抖音都从头重发一遍**

**解法**：所有状态文件改到 `context.getExternalFilesDir(null)`
（`/sdcard/Android/data/com.ss.android.ugc.aweme/files/`），这个目录免权限可写、文件管理器可见。

### 4.2 `status=2` 不等于送达

本地轮询消息状态拿到的 2/5 只说明 SDK 收下了。判真送达只能靠接收方确认。
反过来说，**接收方全收到而服务端只记了几条 send_ok 是正常的**——状态轮询慢会让上报滞后。

## 5. 方法论总结（换版本时照这个走）

```
1. 先 grep dex 确认类/方法是否真的改了名，别一上来就假设"混淆了"
   for n in getIMHandlerCenter createMessageBuilder getConversationListModel; do
       grep -l "$n" *.dex; done

2. 用 dexdump 定位类在哪个 dex，再单 dex 反编译（比整包快一个数量级）

3. 看调用链，不要看类名猜意图
   典型陷阱：hook 的回调只是"判条件"，真正干活的是同类的另一个回调

4. 抽象基类上的 hook 要考虑子类重写

5. 状态文件路径必须落在 App 私有目录（Android 13+）

6. 每一步上报到服务端，否则日志写不进去时完全瞎跑
```
